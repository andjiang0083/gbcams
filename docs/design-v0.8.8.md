> 生成时间: 2026-09-30 · 依据: v0.8.7 真机验收反馈 (黑边 HUD 残影 / 人像模式是失败产物 /

## 1. 真机反馈 → 判断 → 决策

| # | 反馈 (v0.8.7 真机) | 归因 | v0.8.8 决策 |
|---|---|---|---|
| 1 | 黑边里 HUD 文字残留、`CLASS` 压 `GB`、FPS 叠影 | **我们的 bug**: `VIEW_SCALE 1.125` 后画面只覆盖 `x=0..179`, `x=180..239` 保留上一帧内容, 而滤镜名画在 `(2,2)`、FPS 画在右上 `x≈196` — 恰好都落在那条带里。1.5× 时画面铺满整屏, 这个隐患从没暴露过 | 侧栏每帧先清 `fillRect(180,0,60,135)`; 布局改 A 方案 |
| 2 | 帧率 15-17 | v0.8.6 也是 16-17 → **不是回归**, 是 ESP-NOW 大包 + 逐像素滤镜的真实水位 | 不做性能改动 |
| 3 | "中途会卡", DROP 数字同步跳动, <1s, 一瞬间 | 旧版丢一包 → 那块留上一帧内容**照样渲染**(不卡但有脏块); v0.8.7 严格去重后 → 该帧永不"收齐" → 60ms 超时**整帧丢弃** → 上一帧多停 60ms = 用户看到的"卡一下" | **软接收**: 只缺 1 块就用现有数据出帧 |
| 4 | 人像模式是失败产物 | 主观效果不成立 + 白吃 3-6ms/帧 | 整块删除 (`applyPortrait()` / `v` 键 / NVS 字段 / HUD 图标) |
| 5 | 要求 help 体系做完整, 取景也能 `h`, 中英双语, 风格一致 | — | 公共版式 + 取景 3 页 + 相册 2 页 |

### 布局取舍 (真机讨论结论)

| | 画面 | 取景=成品 | 残影 | HUD 位置 |
|---|---|---|---|---|
| 现状 v0.8.7 (整幅+黑边) | 180×135 | ✅ | ❌ 条带没人清 | 压在画面上 |
| **A (v0.8.8 采用)** | 180×135 | ✅ | ✅ 从设计上消失 | 右侧 60px 侧栏 |

## 2. 取景版式 (最终)

```
x: 0 ...................... 179 | 180 ..... 239
   ┌───────────────────────────┬──────────────┐
   │                           │ GB           │ 2   滤镜短名 (无编号 — 用户: "都是数字, 顺着按")
   │   画面 160×120 @1.125     │ FRM2         │ 16  + mini 相框预览 20×14 (y=28)
   │   → 180×135 (整幅 4:3)    │ ▢            │
   │                           │ EV+1         │ 46  仅非 0 时
   │   全幅可见, 不裁切        │ ESP-NOW      │ 58  模式 (v0.8.7 遗留: 只赋值没显示)
   │   取景 == 保存的照片      │ 16.2FPS      │ 70
   │                           │ DROP 3       │ 88  事件式: 掉帧后 5s
   │                           │ CAPT0021     │ 106 事件式: 拍照后 1.5s
   │                           │ h help       │ 124 常驻 dim 提示
   └───────────────────────────┴──────────────┘
```
实现要点:
- `finishFilter()`: `fillRect(SIDEBAR_X,0,60,135)` **先清侧栏** → `pushRotateZoom(pivot 90, 67)` 画面靠左
  → `drawOverlay()` 只画侧栏 → `pushSprite`。画面区被 pushRotateZoom 完全覆盖, 只有侧栏需要清。
- 侧栏强制 `setFont(&fonts::Font0)` (帮助页可能留下 efont 状态), 全部 ASCII, 单行 ≤9 字符 (56px)。
- 拍照反馈文件名截到 9 字符 (侧栏只有 56px)。

## 3. help 体系 (中英双语)

**公共版式** (5 页共用): 橙色标题条 16px (`HELP <中文> <ENGLISH>` + 右对齐页码) → 行区 `y=17` 起、
行距 14 (最多 7 行) → 分隔线 `y=117` → dim 底栏 `h 关闭 Close / Tab 下一页 Next / e 上一页 Prev`。
一行三段: 中文标签 (橙, `x=6`, efontCN_12) | 键位 (黄, `x=58`) | 英文 (dim, 右对齐)。

| 页 | 入口 | 内容 |
|---|---|---|
| 取景 1/3 键位 | 取景 `h` | 滤镜 1-9 / 相框 0 `,` `/` / 曝光 `-` `+` / 快门 Enter / 相册 `r` / 帮助 `h` |
| 取景 2/3 对照表 | `Tab` | 9 滤镜名称 ↔ 1-9 键位; 相框 FRM1-4 名称 (DMG经典/GBC紫框/CRT双线/拍立得) |
| 取景 3/3 状态 | `Tab` | 帧率 / 丢帧 `T# O#` / 软接 `S#` / 解码失败 / 内存 / PSRAM / 版本 — 无串口时的诊断入口 |
| 相册 1/2 BROWSE | 相册 `h` | 移动 / 翻页 / 打开 / 删除(含多选) / 视图 / 缩略图 |
| 相册 2/2 VIEWER | `Tab` | 翻看 / 对比 / 信息 / 幻灯 / 收藏 / 删除 / 返回 |

- 中文走 **M5GFX 内置 `fonts::efontCN_12`** (GB2312, 12×12px, 无需额外字体库), ASCII 走内置 6×8;
  `drawAuto()` 按字节范围自动切字体并按 6/12px 累加宽度, 汉字行 `y+2` 与 ASCII 基线对齐。
- 关闭只用 `h` / `q` (沿用 v0.8.4i 结论: 不用"任意键" — `isChange` 在松键也触发, 会让帮助页一闪而过)。
- 取景帮助打开时**不消费帧** (画面停在帮助页, 视频继续接收), 关闭后下一帧立即恢复 (≈60ms 陈旧, 无副作用)。
- 代价: efont 字库使固件 `.rodata` +151KB (总镜像 1,530,491 B, Flash 占用 45.8%)。

**刷机前 PC 重渲染核对** (设备字宽 6/12px 模型): 全部行位宽 ≤198px, 无三列重叠、无越界
→ `docs/v088-prerender-check.png`。

## 4. 丢帧: 软接收 (soft accept)

```
帧超时 (FRAME_TIMEOUT_MS) → 主循环只置 s_frame_abort_req
        ↓ (回调, 单侧所有权)
只缺 1 块 (s_recv_pkts + 1 >= s_total_pkts) 且非超限?
  ├─ 是 → 用现有数据出帧 (缺的那块保留上一帧内容, 1450B ≈ 15px 高的一条), g_soft_frames++
  └─ 否 → 整帧丢弃, g_drop_frames++ / g_drop_timeout++, 侧栏 DROP 提示
```
算例 (9 包/帧, 丢包率 p≈1.5%): 帧丢率 = 1-(1-p)⁹ ≈ 12.7%; 其中绝大多数只缺 1 块 → 软接收几乎全部救回,
画面不再出现 60ms 空挡。真正丢弃的只剩"缺 ≥2 块"(p² 量级) 与"帧超 32KB"(O)。

## 5. 验收清单 (真机)

1. **侧栏无残影**: 连续切滤镜 (1→2→3…) 与切相框 — 左上角不再留旧滤镜名, FPS 不再叠影。
2. **HUD 不压画面**: 画面区 (x<180) 内看不到任何文字; 拍照反馈出现在侧栏而非画面中央。
3. **侧栏内容**: 滤镜短名 / FRM+mini / EV+1 / ESP-NOW / FPS / `h help` 各就各位, 无越界 (行高 12px)。
4. **取景 help**: 按 `h` 出帮助页, `Tab` 翻到 2/3、3/3, `e` 回退, `h`/`q` 关闭后取景立即恢复;
   中文清晰可读, 三列不压字。
5. **相册 help**: `h` 仍是同一套版式 (2 页), 与取景帮助风格一致。
6. **人像模式已消失**: 相机模式按 `v` 无任何反应 (画面/侧栏都不变); 相册模式 `v` 仍是"全部/收藏"。
7. **不再"卡一下"**: 运行 2-3 分钟, 目视帧率应仍 16-17; 若出现 DROP, 进帮助 3/3 页看 `T/O/S` 计数
   (`S` 增长说明软接收在起作用; `O` 增长说明有帧超过 32KB — 那要从 CAMS3 端降 JPEG 质量解决)。
8. **NVS 兼容**: 升级前若开着相框, 升级后相框状态应保留 (ver 1 blob → ver 2 读取兼容)。

## 3b. 真机反馈修复: 中英混排对齐 (同版重刷)

真机反馈"英文靠上、汉字靠下, 不对齐"。不再凭手感调偏移, 而是把两种字体在屏上的**墨水盒**从库数据里解出来:

| 字体 | 来源 | 墨水相对同一 y | 中心 |
|---|---|---|---|
| Font0 (内置 6×8 GLCD) | `lgfx_fonts.cpp:2209` `GLCDfont{font, font0_info, 6, 8, 7}`; 列位图第 i 位 = 第 i 行, 大写字母 0x7E → 位 1..6 | `y+1 .. y+6` | +3.5 |
| efontCN_12 汉字 | `lgfx_efont_cn_12[213444]` 前 23 字节即 u8g2 表头 (max_char_height=12, y_offset=-2); 字形实测 `char_y=-2, h=12` | `y+0 .. y+11` | +5.5 |

两次 `y_offset` 调整在 `LGFXBase` 与 `U8g2font::drawChar` 里相互抵消, 故墨水盒只取决于 cursor y。
**结论: 汉字画在 `y-2` 时两者墨水中心重合** (原值 `+2` → 实机偏低 4px, 正是反馈现象)。

随版重排: 行区 `y=20` 起 (汉字墨水自 y-2 起, 须在标题条 0..15 + 分隔线 16 之下), 行距 14,
分隔线 117, 底栏 120 (汉字墨水 118..129, 屏高 135)。干跑核对: 全部行位宽 ≤198px, 列/行零碰撞。

同版一起做的 **键位全大写** (用户要求, 全部界面): 帮助页键位列 (`ENTER` / `R` / `H` / `TAB` / `BS` / `A D 左右`)、
底栏 (`H 关闭 CLOSE  TAB 下一页 NEXT`)、取景侧栏 (`H HELP`)、相册提示栏
(`A/D W/S nav  ENTER open  H help  Q quit`、`ENTER mark  BS del marked  Q exit`、`A/D nav  Q back  H help`)。
版本号沿用 v0.8.8 (未验证的候选版不另开号), 重刷并回读校验。
